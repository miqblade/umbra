# Архитектура Umbra

## Цели (от владельца проекта)
1. Настоящее разделение сети по профилям и программам: у каждого свой сетевой стек/туннель, при падении туннеля трафик не уходит в обход (kill-switch), реальный выходной IP виден в интерфейсе.
2. Конфиденциальность: данные только внутри зашифрованного сейфа (VeraCrypt), вход по паролю / паролю и коду / без входа (на выбор), 5 неверных попыток уничтожают сейф, паника одной кнопкой.
3. Отзывчивый рабочий стол на i5-10400F / 16 ГБ / RX 580.
4. Платформа для собственного софта (SEO и другое): модули, которые работают в сетевом окружении выбранного профиля.

## Слои
- **Umbra.Core** (готово, .NET 8, без сторонних пакетов): `Crypto` (scrypt, AES-GCM, TOTP), `Security.Gate` (формат `umbra.dat`, совместим с Python-версией 4.x), `Vault` (аргументы VeraCrypt, уничтожение), `Model` (профили, сетевые политики), `Modules` (описание и обнаружение модулей), `Engine` (интерфейс движка).
- **Движок рабочего стола** (`IDesktopEngine`): где выполняются браузеры и программы. Сменяемая часть.
  - WSL2/WSLg: сетевые пространства Linux (по одному на профиль: WireGuard/OpenVPN, nftables), GPU через WSLg. Проверка на RX 580 — первый эксперимент (см. ROADMAP).
  - QEMU-VM: существующая ветка Umbra Linux 0.2; запасной вариант.
- **Umbra.App** (следующий этап, WPF): окно входа, боковая панель профилей с живым IP, панель модулей, статусы, пауза/паника.
- **Модули** (`modules/<имя>/module.json`): `process` (программа в окружении профиля), `web`, `native`. Манифест проверяется: безопасный id, точка входа только внутри папки модуля, известные разрешения.

## Принципы безопасности
- Нет сторонних зависимостей в ядре; scrypt, TOTP и обёртки написаны на стандартной библиотеке и проверены по векторам RFC и по файлам Python-версии.
- Счётчик попыток хранится на диске; на пятой неудаче `Gate.Login` возвращает `WipeRequired`, дальнейшие попытки отклоняются.
- Режим «без входа» — удобство, не защита: пароль защищён DPAPI (только тот же пользователь Windows на этом ПК).
- Известное ограничение: пароль VeraCrypt передаётся в командной строке на время запуска (особенность CLI); в журналы он не попадает (`Redacted()`).
- Не реализуется и не будет: обход шифрования куки Chrome (App-Bound Encryption) и любые способы выгрузки чужих сессий.
